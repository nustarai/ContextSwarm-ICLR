# Formal Figure 4: six datasets × four allocators × three repeats

This directory is the commit-bound manifest matrix requested for the formal
Issue #39 allocator run.  It contains 6 × 3 × 4 = 72 leaves.  A paired wave
contains one leaf for each allocator on each dataset (24 independent CPS
experiments); the repeat seed changes between waves `1729`, `1730`, and
`1731`.

Every leaf uses `max_parallel = 24` and `aisw.max_in_flight = 24`.  Within a
dataset/repeat block, the four leaves share the same task order, model,
selector identity, horizon, evaluator/Judge contract, candidate transfer,
and runtime limits.  Only `allocation.policy` differs.

The selector is the frozen remote Figure 3 engineering identity:

```text
selector_name      = recency
selector_version   = icpc_formal_v1
primary_sort       = commit_seq_desc
selection.seed     = 1729
identity           = 5dae09c95a6a15c9744a884e495d64fb3f1c1207d5be64f58e282b2e0d5eae0a
```

The three-repeat choice is intentional for this run.  It is a small-sample
engineering validation, not an eight-repeat publication-strength confidence
claim.  The formal selection rule and downstream report must retain this
limitation explicitly.

Judge URLs, NuRouter node configuration, declaration-index paths, and all
credentials are operator-local runtime capabilities.  They must be supplied
by the launcher and must not be added to these manifests.

The files are generated by
`scripts/generate_figure4_formal_matrix.py`; regenerate only before a commit,
then verify the complete manifest closure and image revision together.
